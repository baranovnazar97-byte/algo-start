# Первый выпуск, домен и следующие обновления

Все команды выполняются в PowerShell из корня проекта:

```powershell
cd C:\Users\vnuk\Documents\Project
```

## 1. Необязательный локальный просмотр этапа 1

```powershell
.\stage-1.cmd -Preview
npm run dev
```

Откройте `http://localhost:5173`. Для остановки нажмите `Ctrl+C`.
Этот режим ничего не отправляет в GitHub и на VPS. После просмотра отдельно
выполните реальный выпуск из следующего пункта.

## 2. Первый реальный выпуск

```powershell
.\stage-1.cmd
```

Не запускайте `deploy.cmd` перед этой командой. `stage-1.cmd` самостоятельно:

1. проверит сборку и тесты;
2. создаст коммит этапа 1 и отправит его в `main` на GitHub;
3. при первом запуске попросит вход в GitHub;
4. попросит пароль `root` от VPS и установит SSH-ключ;
5. установит Docker на пустой Ubuntu VPS;
6. запустит PostgreSQL, backend, frontend и Caddy.

Когда SSH впервые покажет fingerprint сервера, сверьте его с панелью VPS и
ответьте `yes`. При вводе пароля символы не отображаются, это нормально.

После завершения проверьте:

- `http://81.90.25.140`
- `http://81.90.25.140/api/health`
- `https://github.com/baranovnazar97-byte/gaming-simulator`

## 3. Записи Cloudflare

После покупки домена добавьте его в Cloudflare и замените NS-серверы у
регистратора на те два адреса, которые покажет Cloudflare.

В разделе **DNS - Records** удалите конфликтующие парковочные записи и создайте:

| Type | Name | Content | Proxy status |
|---|---|---|---|
| A | `@` | `81.90.25.140` | DNS only |
| CNAME | `www` | ваш домен, например `example.ru` | DNS only |

Не создавайте запись AAAA, пока у VPS нет проверенного IPv6. В панели VPS или
сетевом firewall должны быть разрешены входящие TCP-порты `22`, `80` и `443`.

Проверьте, что домен уже возвращает IP сервера:

```powershell
Resolve-DnsName example.ru
Resolve-DnsName www.example.ru
```

Вместо `example.ru` везде укажите купленный домен.

## 4. Подключение домена и HTTPS

Когда обе DNS-записи начали возвращать `81.90.25.140`, выполните:

```powershell
.\setup-domain.cmd example.ru
```

Команда настроит основной адрес и `www`, запросит сертификат и в конце напечатает
адрес `https://example.ru`. Если вариант `www` не нужен:

```powershell
.\setup-domain.cmd example.ru -NoWww
```

После успешного открытия HTTPS в Cloudflare:

1. откройте **SSL/TLS - Overview** и выберите `Full (strict)`;
2. включите **SSL/TLS - Edge Certificates - Always Use HTTPS**;
3. вернитесь в DNS и переключите обе записи с `DNS only` на `Proxied`.

Режим `Flexible` использовать нельзя.

## 5. Еженедельные выпуски

Через неделю выполните только:

```powershell
.\stage-2.cmd
```

Затем по одной команде в неделю:

```powershell
.\stage-3.cmd
.\stage-4.cmd
.\stage-5.cmd
.\stage-6.cmd
```

Каждая команда создаёт отдельный Git-коммит, отправляет его в GitHub и обновляет
тот же VPS. Домен, HTTPS, база и пользовательские данные сохраняются.

`deploy.cmd` нужен только для повторной отправки уже текущей версии на VPS,
например если GitHub обновился, а VPS временно был недоступен. Для очередного
еженедельного этапа используйте только соответствующий `stage-N.cmd`.
