## Недельный выпуск в GitHub и на VPS

Репозиторий проекта: <https://github.com/baranovnazar97-byte/gaming-simulator>.

Проект подготовлен к шести последовательным публикациям. Используйте строго по
одной команде в неделю:

```powershell
.\stage-1.cmd
.\stage-2.cmd
.\stage-3.cmd
.\stage-4.cmd
.\stage-5.cmd
.\stage-6.cmd
```

Каждая команда открывает следующий набор функций, создаёт отдельный Git-коммит
и обновляет VPS. Пропустить этап или случайно запустить следующий раньше нельзя.
Полное содержание этапов и режим локального предпросмотра описаны в
[`STAGES.md`](STAGES.md).

На Windows из корня проекта выполните одну команду:

```powershell
.\release.cmd "Краткое описание реального обновления"
```

Команда проверяет сборку и тесты, создаёт коммит, отправляет его в `main`,
затем разворачивает ту же версию на `81.90.25.140`. При первом запуске она
может установить Git for Windows, открыть вход в GitHub и попросить пароль
`root` от VPS. Следующие обновления используют отдельный SSH-ключ из локальной
папки `.deploy`, которая не попадает в Git.

Только обновить VPS без нового Git-коммита:

```powershell
.\deploy.cmd
```

Учебный курсовой проект: многостраничное веб-приложение, в котором ребёнок регистрируется, выполняет короткие игровые задания, получает очки и видит свой прогресс.

Проект намеренно сделан понятным для защиты в колледже: React + TypeScript на клиенте, NestJS + модуль `pg` на сервере, PostgreSQL для хранения пользователей и результатов. ORM и сложные микросервисы не используются.

## Возможности

- регистрация и вход;
- четыре мини-игры: «Шаг за шагом», «Робот-почтальон», «Ловец ошибок» и «Если — то»;
- несколько уровней, очки, открытие следующих заданий;
- личная страница прогресса;
- адаптивный детский интерфейс;
- единый запуск клиентской части, API и базы данных через Docker Compose.

## Быстрый запуск через Docker

Нужны Docker Desktop (Windows/macOS) либо Docker Engine с Compose (Linux).

```powershell
Copy-Item .env.example .env
```

Откройте `.env`, обязательно замените `POSTGRES_PASSWORD` и `JWT_SECRET`, затем выполните:

```powershell
docker compose --env-file .env up -d --build
```

Сайт: <http://localhost:8080>. Проверка API: <http://localhost:8080/api/health>.

Состояние и журналы:

```powershell
docker compose ps
docker compose logs -f
```

Остановка без удаления данных:

```powershell
docker compose down
```

Том PostgreSQL сохраняется. Команда `docker compose down -v` удалит и контейнеры, и данные — для обычной остановки её не используйте.

## Запуск для разработки

Понадобятся Node.js 20+ и локальный PostgreSQL. Настройки сервера приведены в `backend/.env.example`.

Установите зависимости и запустите frontend вместе с backend одной командой:

```powershell
npm install
npm run install:all
npm run dev
```

Сервер автоматически читает сначала `backend/.env`, затем корневой `.env`. В репозитории уже создан локальный `.env` с `DB_USER=postgres` и `DB_PASSWORD=root`.

Для раздельного запуска можно использовать команды ниже.

```powershell
npm run dev:backend
```

Во втором терминале:

```powershell
npm run dev:frontend
```

Клиент будет доступен на <http://localhost:5173>, API — на <http://localhost:3000/api>.

## Команда

Роли указаны как зоны ответственности, а не как вымышленная история авторства:

| Роль | Зона ответственности |
|---|---|
| Участник 1 | тестирование, развёртывание и документация |
| Участник 2 | frontend и дизайн |
| Участник 3 | backend и база данных |

Это назначенные зоны для будущей командной работы, распределённые случайным образом. Перед сдачей замените «Участник 1–3» настоящими ФИО и скорректируйте таблицу по факту. Выполненную работу следует подтверждать задачами, pull request и обычной историей Git.
