# Честный план еженедельной разработки

## Одна команда для недельного выпуска

После того как реальное изменение готово и проверено локально, выполните:

```powershell
.\release.cmd "Краткое описание сделанного изменения"
```

Команда отправляет изменения в
<https://github.com/baranovnazar97-byte/gaming-simulator> и затем обновляет
`81.90.25.140`. Один выпуск должен описывать фактически выполненную работу.

Проект можно показывать как постепенно развивающийся, если каждую неделю действительно выполнять небольшую законченную задачу, проверять её и выпускать новую версию. Не нужно менять даты коммитов, дробить уже готовую работу задним числом или приписывать участникам чужой код.

Если весь MVP уже собран до создания удалённого репозитория, корректный первый commit — единый `Initial MVP`. Дальнейшие записи ниже являются будущим backlog, а не утверждением о выполненной ранее работе.

## Рабочий цикл недели

1. В понедельник выбрать 3–6 задач и назначить ответственных.
2. Делать изменения в короткой ветке `week-N-краткое-название`.
3. Другой участник проверяет код и сценарии приёмки.
4. В пятницу объединить готовое в `main`, поставить актуальный тег и создать краткие release notes.
5. GitHub Actions обновит VPS либо ответственный выполнит две команды из `DEPLOY.md`.
6. Проверить регистрацию, вход, одну игру, запись прогресса и `/api/health`.

## Распределение ролей

| Участник | Основная зона | Дополнительная проверка |
|---|---|---|
| Участник 1 | тестирование, deploy и документация | smoke-test релиза и журнал изменений |
| Участник 2 | frontend и дизайн | удобство игр на телефоне |
| Участник 3 | backend и PostgreSQL | API, безопасность и резервные копии |

Это случайно распределённые зоны для предстоящих итераций и заменяемые обозначения, а не описание уже выполненной работы. Перед сдачей внесите реальные ФИО и скорректируйте таблицу по фактически выполненным задачам.

## Roadmap после базового MVP

| Неделя | Реальное улучшение | Результат/критерий готовности | Версия |
|---|---|---|---|
| 0 | Публикация текущего MVP | Все три контейнера запускаются, доступны регистрация и 4 игры | `v1.0.0` |
| 1 | Улучшение регистрации | Понятные ошибки, проверка полей, тест повторного входа | `v1.1.0` |
| 2 | Новые задания «Шаг за шагом» | Добавлены уровни и объяснение правильного порядка | `v1.2.0` |
| 3 | Улучшение «Робота-почтальона» | Новый маршрут, кнопка очистки команд, мобильная проверка | `v1.3.0` |
| 4 | Новые ошибки для «Ловца ошибок» | Несколько вариантов задания и подсказки после ответа | `v1.4.0` |
| 5 | Расширение игры «Если — то» | Новые ситуации и краткое объяснение условия | `v1.5.0` |
| 6 | Прогресс и мотивация | Улучшена диаграмма/карточки, добавлена простая награда | `v1.6.0` |

Версии примерные: тег создаётся только после успешной проверки, а невыполненная задача переносится без фиктивной отметки «готово».

## Минимальная проверка перед выпуском

- секреты отсутствуют в Git;
- `npm run build` завершается без ошибок;
- backend-тесты проходят;
- `docker compose --env-file .env config --quiet` проходит;
- контейнеры имеют статус healthy;
- новый пользователь может зарегистрироваться;
- результаты игры остаются после обновления страницы;
- сделан дамп БД перед изменением схемы;
- документация соответствует текущему интерфейсу.
