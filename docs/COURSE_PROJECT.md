# Курсовой проект

## ООО «Алгоритмика» (СБЕР). Игровой тренажёр по алгоритмам

> Шаблон пояснительной записки. Название образовательной организации, специальность, группу, ФИО студентов, руководителя и год необходимо заполнить фактическими данными перед сдачей.

## Аннотация

Разработано учебное веб-приложение для знакомства детей с алгоритмическим мышлением. Пользователь создаёт аккаунт, получает доступ к коротким мини-играм, проходит уровни, зарабатывает очки и наблюдает прогресс. Сложность заданий невысокая: интерфейс объясняет последовательность действий, команды, поиск ошибки и простые условия без текстового программирования.

Клиентская часть реализована на React и TypeScript, серверная — на NestJS и TypeScript. Для хранения данных используется PostgreSQL, подключённая непосредственно через пакет `pg`. Приложение разворачивается контейнерами Docker Compose.

Ключевые слова: алгоритм, тренажёр, обучение, мини-игра, React, NestJS, PostgreSQL, Docker.

## Введение

Алгоритмическое мышление — умение представить задачу как понятную последовательность шагов, заметить условие, проверить результат и исправить ошибку. Эти навыки нужны не только в программировании: ребёнок использует их при планировании, решении учебных задач и анализе причин результата.

Обычное объяснение алгоритмов может показаться младшему пользователю абстрактным. Игровой формат даёт короткую цель, немедленную обратную связь и видимый прогресс. Поэтому тема курсовой работы актуальна для начального знакомства детей с информатикой.

Цель проекта — разработать простой веб-тренажёр, обучающий базовым алгоритмическим конструкциям через четыре мини-игры.

Для достижения цели поставлены задачи:

1. определить понятные ребёнку учебные механики;
2. спроектировать страницы, навигацию и модель данных;
3. реализовать регистрацию и аутентификацию;
4. создать четыре мини-игры и систему очков;
5. сохранять прогресс в PostgreSQL;
6. подготовить контейнерный запуск и развёртывание на VPS;
7. проверить основные пользовательские сценарии и оформить документацию.

Объект исследования — цифровое обучение основам алгоритмов. Предмет исследования — веб-приложение с игровыми заданиями, обратной связью и учётом прогресса.

## 1. Анализ предметной области

### 1.1. Пользователь и его потребности

Основной пользователь — ребёнок, начинающий изучать информатику. Ему нужны короткие инструкции, крупные элементы управления, спокойная цветовая схема, отсутствие лишних настроек и понятная реакция на правильный либо неправильный ответ.

Учебная сессия должна укладываться в несколько минут. Ошибка не наказывается потерей данных: пользователь получает подсказку и может повторить действие. Очки используются как простая мотивация, а открытие следующего уровня показывает движение вперёд.

### 1.2. Функциональные требования

- регистрация по имени, электронной почте и паролю;
- вход зарегистрированного пользователя;
- просмотр каталога игр;
- запуск доступного уровня;
- проверка решения и начисление очков;
- открытие следующих заданий;
- сохранение лучшего результата;
- просмотр общего прогресса;
- выход из аккаунта.

### 1.3. Нефункциональные требования

- понятный русскоязычный интерфейс;
- работа на современном компьютере и смартфоне;
- время ответа API в обычной локальной сети — без заметной задержки;
- пароли не хранятся в открытом виде;
- закрытые операции требуют JWT-токен;
- данные сохраняются после перезапуска контейнеров;
- проект запускается одной основной командой Docker Compose;
- код остаётся небольшим и объяснимым на защите.

### 1.4. Ограничения

В рамках курсового проекта не разрабатываются чат, социальная сеть, кабинет учителя, платёжная система и сложный редактор уровней. Это осознанно удерживает объём на учебном уровне. Проект не следует выдавать за официальный продукт ООО «Алгоритмика» или ПАО Сбер без подтверждённого разрешения правообладателей; название в работе рассматривается как заданная тема/учебный кейс.

## 2. Проектирование системы

### 2.1. Архитектура

Применена классическая трёхуровневая схема:

```text
Браузер → React-клиент/Nginx → REST API NestJS → PostgreSQL
```

React формирует страницы и игровые состояния. Запросы с путём `/api` Nginx передаёт серверу. NestJS проверяет входные данные и права пользователя, а затем выполняет параметризованные SQL-запросы через пул `pg`. PostgreSQL хранит аккаунты, справочник игр и результаты.

В Docker Compose работают три сервиса:

- `frontend` — собранное React-приложение и Nginx;
- `backend` — NestJS API;
- `db` — PostgreSQL 16 с именованным томом.

Наружу публикуется только frontend. API и БД находятся во внутренней Docker-сети.

### 2.2. Модель данных

Основные сущности:

| Сущность | Назначение | Основные поля |
|---|---|---|
| Пользователь | аккаунт ребёнка и сумма очков | id, name, email, password_hash, total_score, created_at |
| Игра | описание мини-игры | code, title, description, order_no |
| Уровень | задание и его данные | id, game_code, level_no, max_score, content |
| Прогресс | лучший результат уровня | user_id, level_id, best_score, completed_at |
| Попытка | история завершений уровня | id, user_id, level_id, score, attempted_at |

Для пары «пользователь — игра — уровень» хранится одна актуальная запись. Если уровень пройден повторно хуже, лучший результат не уменьшается. Связь с пользователем позволяет получить личную статистику.

### 2.3. API

| Метод и путь | Назначение | Доступ |
|---|---|---|
| `POST /api/auth/register` | создать аккаунт и выдать токен | открытый |
| `POST /api/auth/login` | проверить email и пароль | открытый |
| `GET /api/auth/me` | получить текущего пользователя | JWT |
| `GET /api/games` | получить справочник игр | открытый |
| `GET /api/progress` | получить прогресс пользователя | JWT |
| `POST /api/progress/complete` | записать результат уровня | JWT |
| `GET /api/health` | проверить состояние API и БД | открытый |

Запрос завершения содержит код игры, номер уровня, набранные и максимально возможные очки. Сервер проверяет типы и допустимые значения; идентификатор пользователя берётся из токена, а не из тела запроса.

### 2.4. Навигация и страницы

- главная страница знакомит с тренажёром;
- регистрация и вход открывают личный доступ;
- каталог показывает четыре игры и доступность заданий;
- страница конкретной игры содержит инструкцию, игровое поле и обратную связь;
- страница прогресса показывает очки и пройденные уровни;
- справочная страница кратко объясняет проект.

## 3. Описание мини-игр

### 3.1. «Шаг за шагом»

Ребёнок видит действия, перемешанные в неправильном порядке. Его задача — расположить шаги так, чтобы получить логичную последовательность. Игра знакомит с линейным алгоритмом: каждый шаг выполняется после предыдущего.

Пример: взять чашку → положить пакетик чая → налить воду → подождать.

### 3.2. «Робот-почтальон»

Нужно составить короткий маршрут из команд движения и привести робота к цели. Пользователь учится заранее планировать команды и проверять их исполнение.

### 3.3. «Ловец ошибок»

Показывается последовательность, в которой один шаг лишний или находится не на своём месте. Ребёнок выбирает ошибку и получает пояснение. Игра развивает навык отладки — поиска причины неверного результата.

### 3.4. «Если — то»

Пользователь читает простую ситуацию и выбирает подходящее действие. Например: «Если на улице дождь, то…». Так вводится понятие условия без формального языка программирования.

## 4. Реализация

### 4.1. Клиентская часть

Frontend написан на React с TypeScript и собирается Vite. Компоненты отвечают за повторно используемые части интерфейса, React Router — за переход между страницами, контексты — за текущего пользователя и прогресс. API-клиент централизованно добавляет JWT-токен и преобразует ошибки в понятный текст.

Игровая логика находится на клиенте, потому что задания небольшие и не требуют сложных вычислений. После успешного решения клиент отправляет итог на сервер. Следует понимать ограничение: такой подход подходит для учебного тренажёра, но не защищает очки от намеренной подмены пользователем.

### 4.2. Серверная часть

Backend построен модульно средствами NestJS: аутентификация, работа с БД, каталог игр, прогресс и проверка состояния. DTO и `ValidationPipe` ограничивают входные данные. Пароль хешируется `bcryptjs`; после входа выдаётся подписанный JWT.

Пул `pg` повторно использует соединения. SQL-запросы параметризованы, что снижает риск SQL-инъекций. Таблицы создаются при запуске простыми SQL-командами — это наглядно для учебной работы. В более крупном проекте понадобился бы отдельный механизм версионированных миграций.

### 4.3. Безопасность

- хеширование паролей;
- JWT для закрытых маршрутов;
- проверка DTO и ограничение размера JSON;
- параметризованные запросы PostgreSQL;
- заголовки Helmet;
- ограничение частоты запросов к авторизации;
- секреты передаются через `.env`, который исключён из Git;
- БД не публикует порт наружу.

Проект рассчитан на учебную демонстрацию. Перед реальным использованием детьми необходимы юридическая проверка обработки персональных данных, согласие законных представителей, политика конфиденциальности, аудит безопасности и полноценные эксплуатационные процедуры.

### 4.4. Контейнеризация

Dockerfile каждой части использует этап сборки. В итоговый frontend-образ попадают статические файлы и Nginx, в backend-образ — production-зависимости и скомпилированный JavaScript. Compose ожидает готовность PostgreSQL и API через healthcheck. Том `postgres_data` отделяет данные от жизненного цикла контейнера.

Первый запуск:

```powershell
Copy-Item .env.example .env
docker compose --env-file .env up -d --build
```

Перед командой значения пароля БД и JWT-секрета заменяются в `.env`.

## 5. Тестирование

Проверяются позитивные и ошибочные сценарии регистрации, входа, игр и сохранения данных. Отдельно контролируются адаптивность, клавиатурная навигация, повторный запуск контейнеров и недоступность закрытого API без токена.

Критический сквозной сценарий:

1. новый пользователь регистрируется;
2. открывает первую игру;
3. решает доступный уровень;
4. получает очки;
5. обновляет страницу;
6. результат сохраняется, а следующий уровень становится доступен;
7. после выхода и повторного входа прогресс остаётся.

Подробные проверки приведены в `TEST_PLAN.md`.

## 6. Развёртывание и сопровождение

Для VPS выбран Docker Compose. Домен направляется A-записью на сервер, а внешний Nginx получает TLS-сертификат Let's Encrypt и проксирует трафик в frontend-контейнер. PostgreSQL хранится в постоянном томе, перед изменениями схемы выполняется дамп.

Еженедельный выпуск состоит из фактически выполненной небольшой итерации, проверки, merge в `main` и двух серверных команд:

```bash
git pull --ff-only
docker compose --env-file .env up -d --build --remove-orphans
```

Допускается запуск этих действий GitHub Actions через SSH. Секреты хранятся в настройках репозитория и `.env` VPS, а не в коде. Подробности приведены в `DEPLOY.md` и `WEEKLY_PLAN.md`.

## 7. Организация работы команды

Предлагаемое базовое распределение:

| Обозначение | Ответственность |
|---|---|
| Участник 1 | тестирование, deploy и документация |
| Участник 2 | frontend и дизайн |
| Участник 3 | backend и база данных |

Зоны случайно назначены для будущей командной работы, а обозначения заменяются реальными ФИО. Таблица служит для планирования и не должна использоваться для фиктивного приписывания уже выполненной работы. Фактический вклад отражается задачами, review и историей Git.

## 8. Ограничения и развитие

Текущая версия является MVP. Возможные направления развития:

- новые уровни без усложнения правил;
- звуковая обратная связь с возможностью отключения;
- кабинет учителя и учебные группы;
- восстановление пароля;
- серверная проверка игровых ответов;
- версионированные миграции БД;
- автоматические end-to-end тесты;
- улучшение доступности для пользователей с особыми потребностями.

Добавлять функции следует небольшими проверяемыми выпусками. Это уменьшает риск и создаёт настоящую, а не искусственно сформированную историю прогресса.

## Заключение

В результате спроектирован и реализован простой игровой тренажёр, охватывающий четыре основы алгоритмического мышления: последовательность, команды, отладку и условия. Архитектура разделяет интерфейс, API и базу данных; PostgreSQL сохраняет аккаунты и результаты, а Docker Compose обеспечивает воспроизводимый запуск.

Поставленная цель достигнута на уровне учебного MVP. Проект остаётся понятным для демонстрации и допускает постепенное развитие через новые задания, тесты и улучшение интерфейса.
