# План тестирования

## Цель

Проверить основные пользовательские сценарии, сохранность данных, базовую защиту API, адаптивность и воспроизводимость контейнерного запуска.

## Окружение

- Chrome/Edge/Firefox актуальной версии;
- ширина экрана 360, 768 и 1366 пикселей;
- Docker Engine с Compose;
- чистая база и база с существующим пользователем.

## Функциональные сценарии

| ID | Действия | Ожидаемый результат |
|---|---|---|
| TC-01 | Зарегистрировать пользователя с допустимыми данными | Создан аккаунт, выполнен вход |
| TC-02 | Повторить регистрацию с той же электронной почтой | Показана понятная ошибка, дубликат не создан |
| TC-03 | Войти с верным паролем | Открыта личная часть |
| TC-04 | Войти с неверным паролем | Доступ не предоставлен |
| TC-05 | Открыть закрытый API без токена | Получен HTTP 401 |
| TC-06 | Вызвать `/api/health` при работающей БД | Получен успешный статус |
| TC-07 | Решить «Шаг за шагом» | Ответ проверен, очки начислены |
| TC-08 | Довести робота до цели | Уровень завершён |
| TC-09 | Найти неправильный шаг | Показана правильная обратная связь |
| TC-10 | Выбрать действие для условия | Ответ проверен |
| TC-11 | Обновить страницу после победы | Прогресс не потерян |
| TC-12 | Пройти уровень повторно с меньшим баллом | Лучший результат не уменьшается |
| TC-13 | Выйти и войти снова | Сохраняется тот же прогресс |
| TC-14 | Выполнить `docker compose up -d --build` | Все сервисы запущены/healthy |
| TC-15 | Перезапустить контейнеры | Пользователь и результаты сохранены |
| TC-16 | Открыть сайт через reverse proxy HTTPS | Страницы и `/api` работают без mixed content |

## Проверки интерфейса

- текст не выходит за карточки на 360 px;
- все основные действия доступны клавишей Tab;
- фокус видим;
- у кнопок понятные подписи;
- цвет не является единственным признаком ошибки/успеха;
- нет горизонтальной прокрутки страницы;
- состояние загрузки не выглядит как зависание.

## Проверки безопасности

- пароль отсутствует в ответах API и таблице в открытом виде;
- SQL-инъекция в поле электронной почты не даёт доступ;
- лишнее поле DTO отклоняется;
- результат нельзя записать для чужого `userId` из тела запроса;
- `.env` не отслеживается Git;
- PostgreSQL не публикует порт хоста;
- частые попытки входа ограничиваются.

## Smoke-test после еженедельного релиза

1. Проверить `docker compose ps`.
2. Вызвать `/health` и `/api/health`.
3. Открыть главную, вход и каталог.
4. Войти тестовым аккаунтом.
5. Завершить один уровень и обновить страницу.
6. Просмотреть последние журналы backend/frontend.

## Критерии приёмки

Релиз считается готовым, если TC-01, TC-03, TC-05—TC-16 проходят, критических ошибок нет, а известные некритические ограничения записаны в release notes.
